Service and routes for lists and their items: create, rename, archive, add/edit/remove items, reorder, mark bought. A list is a named collection of `(catalog_item, quantity, unit)`.

Plain, boring CRUD deliberately landed before any AI touches the domain, so the data model is proven independently of model behaviour.

## Acceptance criteria
- [ ] Full CRUD for lists and items, **owner-scoped via `user_id`** — see note below
- [ ] Items can exist before canonicalization (a raw free-text item is valid)
- [ ] Demo session rejected on all mutations
- [ ] typecheck + lint + test green

**Scope note (amended at plan review, task 064).** The original wording said "household-scoped".
Lists are implemented **owner-scoped via `user_id`**, consistent with all 9 existing domains and with
9.1's decision: `withSharing()` is dead code with no grant path (`shopping_list` is not a sharing
resource type, and `POST /api/sharing-grants` does not verify resource ownership), so a sharing-aware
query would change no behaviour while adding untested SQL. Household visibility for lists is deferred
to the same repo-wide sharing rollout that pantry/habit (9.1) await. Record:
[`tasks/064-shopping-lists-crud/TASK.md`](./064-shopping-lists-crud/TASK.md).
