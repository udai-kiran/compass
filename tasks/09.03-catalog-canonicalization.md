`catalog_items` gives an item one canonical identity and a normalized unit, so "atta 5kg" and "wheat flour 5kg" resolve to the same thing and can be price-compared honestly.

Adds `unitPricePaise` to `packages/shared/src/money.ts` alongside `rupeesToPaise`/`formatINR`, plus unit conversion (g↔kg, ml↔L, piece counts) in integer arithmetic — no float rupees, and no float grams that round badly at scale.

**An ambiguous match is a review step, never a silent guess** — the same discipline as `matchAccount`/`matchCategory` in the extractor, where only a unique hit wins.

## Acceptance criteria
- [ ] `unitPricePaise` computes ₹/kg and ₹/L correctly across mixed units, in integer math
- [ ] A unique match auto-links; an ambiguous match is surfaced for review and never auto-resolved
- [ ] Unmatched items remain usable rather than blocking the list
- [ ] Canonicalization never invents a catalog entry without user confirmation
- [ ] typecheck + lint + test green
