2.0.0 is an architectural reset with almost no user-visible surface, so the documentation *is* the deliverable for anyone who has to work on this afterwards.

- **`CLAUDE.md`** — the module layout replacing "write new logic in `services/`, not `repositories/`"; the domain event bus replacing the URL-regex hook; and the **double-entry ledger model**, which invalidates the current description of transactions entirely.
- **`ROADMAP.md`** — move the migration and double-entry work from "going" to "available", and restate the release sequence.
- **`apps/docs`** — refresh `architecture/overview.md` and `architecture/data-model.md`; add a page on the postings model explaining why an expense is two legs and where category lives.
- **`PRD.md`** — note that the ledger is double-entry; the product framing is unchanged.
- **`tasks/README.md`** — regenerate the index with final statuses.

The postings explanation matters most. Anyone reading the schema cold will otherwise wonder why there is one `Expenses` account instead of a category tree, and the answer — category is a dimension, not an account — needs to be written down once rather than rediscovered.
