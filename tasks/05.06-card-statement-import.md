Card-specific CSV presets on the existing import pipeline (sign conventions, EMI line handling), mapping payments to transfer links with the paying bank account.

## Acceptance criteria
- [x] At least two card-format presets ship
- [x] Card payments auto-link as transfers, not expenses
- [x] Statement total reconciles against imported rows

## Implementation
- Two card presets in `BANK_PRESETS`: "HDFC / Amex Credit Card" (single `Amount` column, Dr/Cr suffix → outflow/inflow via `parseAmountCell`) and "ICICI / SBI Credit Card" (separate `Amount (Dr)`/`Amount (Cr)` columns). Distinctive columns keep `suggestMapping` from colliding with the bank presets.
- `autoLinkTransfers` (transfers service): after commit, links exact opposite-amount cross-account pairs within the 3-day window, but only when each leg has a single candidate (ambiguous matches left for manual review) — so a card payment credit links to the paying-account debit as a transfer, not income. `commitImport` calls it and returns `linkedTransfers` + `netPaise`.
- `CommitResult` gained `netPaise` (signed sum of imported rows, to reconcile against the statement total) and `linkedTransfers`; the import UI surfaces both in the commit toast.
- Verified end-to-end: card statement (₹1,500 Dr purchase + ₹5,000 Cr payment) auto-mapped, purchase −150000 / payment +500000, payment auto-linked to a matching bank debit (`linkedTransfers: 1`), net ₹3,500 reconciles.
