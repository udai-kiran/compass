A typed in-process event emitter so domains announce what happened instead of callers pattern-matching URLs. Net-new — there is no `EventEmitter` anywhere in `apps/api` or `packages/` today. Not to be confused with `services/ai/events.ts`, which is the AI event *log*.

Events emitted by services after a successful write, e.g. `ledger.mutated { userId }`. Subscribers register at boot in `app.ts`. Delivery is fire-and-forget with per-subscriber error isolation — a throwing subscriber must never fail the request that emitted, mirroring how `AiObserver` is invoked in `packages/ai/src/http.ts`.

## Acceptance criteria
- [ ] Typed event map — emitting an unknown event or a wrong payload is a compile error
- [ ] A subscriber that throws is logged and swallowed; the emitting request still succeeds
- [ ] Subscribers run without blocking the response path
- [ ] Unit tests cover emit/subscribe, error isolation, and multiple subscribers per event
