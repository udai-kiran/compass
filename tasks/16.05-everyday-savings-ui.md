> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Files:** `src/routes/shopping/SavingsPage.tsx`, `src/routes/shopping/FoodDeliveryPanel.tsx`, `src/routes/shopping/CabPanel.tsx`.

- **Realized savings** — actual saving and **money left on the table**, by platform, category and card. Also show **predicted versus actual**: if the optimizer's recommendations did not hold up against real receipts, display that. A savings tracker that only measures the user and never itself is marketing.
- **Food delivery** — per-order comparison including delivery, platform, packaging fees and GST, but lead with the pattern: *"₹7,400 last month across 23 orders, ₹1,900 of it fees."*
- **Cabs** — per-trip comparison where fares are observable, and the recurring-commute insight, which is worth far more: *"₹4,100 last month, 60% one commute — a metro pass is ₹1,500."*

Both verticals must be **fully useful with no live price data**, on ledger spend analysis alone. Fare and price estimates are labelled with their observation time; surge moves minute to minute and the UI must not imply precision it lacks.

Information, never nagging. No guilt framing about ordering in or taking cabs.

## Acceptance criteria
- [ ] Realized saving and money-left-on-the-table by platform, category and card
- [ ] Predicted-vs-actual recommendation quality displayed
- [ ] Food and cab panels useful with zero live price data
- [ ] Recurring-commute and repeat-order patterns surfaced from ledger history
- [ ] Estimates labelled with observation time; no false precision
- [ ] Neutral tone; no guilt framing
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
