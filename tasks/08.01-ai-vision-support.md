Hard prerequisite for every photo-based capture idea. Today `packages/ai/src/types.ts:82-84` types every message as `content: string`, no provider has an image path, and there is no OCR anywhere in the repo (`pdfjs-dist` in the extractor only extracts statement *text*).

Extend the message union to carry image blocks alongside text, and implement the native wire shape for **anthropic** and **openai-compat**. **Skip ollama**, exactly as forced tool-calling deliberately skips it — call sites gate on `ai.name !== "ollama"`.

Follow the shape of commit `5bbc546`: transport type → pre-flight guard that throws before any HTTP → per-provider wire shape → provider tests asserting the exact JSON sent. Keep the `AiObserver` contract intact (fired once per call regardless of retries), and keep images out of the logged request context where they would bloat `ai_events`.

## Acceptance criteria
- [ ] Message union carries image content without breaking any existing text-only call site
- [ ] Anthropic and openai-compat send the correct native image wire shape (asserted in tests)
- [ ] Sending an image to ollama fails fast with a clear error, before any HTTP call
- [ ] Oversized/unsupported image types rejected with a typed error
- [ ] `ai_events` records that an image was sent without embedding the image bytes
- [ ] Existing `packages/ai` tests still green; app still boots with AI disabled
- [ ] typecheck + lint + test green
