> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Files:** extend `src/routes/emis/EMIsPage.tsx` with a prepay panel; new `src/routes/goals/WindfallPanel.tsx`.

- **Rate-reset impact** — floating rates reset constantly and lenders usually hold the EMI flat while extending the tenure, which hides the cost entirely. Make it visible: *"8.5% → 9.0%: EMI unchanged, tenure +14 months, ₹4.2L extra interest."*
- **Prepay vs invest** — interest saved beside post-tax expected return, with the **risk asymmetry stated explicitly**. Interest saved is certain; investment return is not. Rendering 9% guaranteed next to 12% assumed as if comparable would be actively misleading, so label them.
- **Tenure-reduction vs EMI-reduction** prepayment shown separately — very different total-interest outcomes.
- **Windfall allocator** — a lump sum routed through the goal engine, with impact expressed in **months pulled forward**, not just rupees.

Both panels must be willing to conclude **"neither — build the emergency fund first"**, and that outcome should look like a real answer rather than an error state.

## Acceptance criteria
- [ ] Rate-change impact on EMI, tenure and total interest
- [ ] Prepay vs invest with risk asymmetry explicitly labelled, not implied
- [ ] Tenure-reduction and EMI-reduction modelled and displayed separately
- [ ] Windfall impact stated in months pulled forward per goal
- [ ] Emergency-fund-first and high-interest-debt-first outcomes render as valid answers
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
