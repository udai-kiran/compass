> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**The centrepiece of the shopping surface, and a direct descendant of `src/routes/inbox/InboxPage.tsx` (530 L) — read that file before starting.** Reuse its structure: pre-filled editable draft cards, a provenance strip showing where each item and price came from, an action bar, and escape hatches that degrade a wrong guess rather than trapping the user.

**Files:** `src/routes/shopping/CartPage.tsx`, `src/routes/shopping/cart-view.ts` (+ `.test.ts`).

Show, inline and **before** the accept action:
- the per-platform split with delivery fees, minimum-cart thresholds and **delivery ETA** (serviceability from 10.2 — a non-serviceable platform must not appear as an option)
- the recommended card, with the offer cap arithmetic made visible: *"10% back, capped ₹1,500 — you reach the cap at ₹15,000"*
- the **budget cap** overage and the **goal-impact** figure from 11.3
- every price with its source and observation time — crowdsourced data is **not** presented as live truth

**Nothing is ordered and nothing is paid.** The user accepts a draft; the app never checks out. Make that unmistakable in the copy — a button reading "Buy" would be a lie.

## Acceptance criteria
- [ ] Draft cards with editable fields and a provenance strip, per the `InboxPage` pattern
- [ ] Platform split shows fees, thresholds and ETA; non-serviceable platforms excluded
- [ ] Card recommendation shows cap arithmetic, not just a headline percentage
- [ ] Budget overage and goal impact shown before accept
- [ ] Every price labelled with source and observation time
- [ ] Copy makes clear nothing is ordered or paid; no "Buy" affordance
- [ ] Escape hatches degrade a wrong guess instead of trapping the user
- [ ] Pending-cart count badge in the sidebar, as `useInboxCount()` does
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
