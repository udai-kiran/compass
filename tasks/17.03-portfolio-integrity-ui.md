> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Files:** extend `src/routes/investments/PortfolioPage.tsx` with an attribution panel; route fraud findings into the existing `src/routes/inbox/InboxPage.tsx` review queue.

- **Attribution** — decompose return into appreciation, income, realised and unrealised, and above all **contributions versus market movement**. That last split is the one most people get wrong: a portfolio growing because money was paid into it is not a portfolio performing, and showing them separately is the single most honest thing this panel can do.
- **Benchmark** only when the user explicitly selects one. Never auto-assign an index the portfolio was never trying to track.
- **Integrity findings** (duplicate charges, subscription price rises, missing refunds, post-cancellation charges) go into the **existing review inbox**, not a new notification stream — one place for "something needs your attention". Dismissals must be remembered.

## Acceptance criteria
- [ ] Return decomposed into appreciation, income, realised and unrealised
- [ ] Contribution effect shown separately from market effect
- [ ] Benchmark comparison only on explicit user selection
- [ ] After-tax return shown where available and clearly labelled when not
- [ ] Integrity findings render in the existing inbox with remembered dismissal
- [ ] Charts built from `viz.tsx` primitives only
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
