Two `AiProvider` implementations selected by env: Anthropic API (`ANTHROPIC_API_KEY`) and local Ollama (`OLLAMA_BASE_URL`). Timeouts, retries, and structured-output validation with shared Zod schemas.

## Acceptance criteria
- [x] Provider chosen purely by env config; swap requires no code change
- [x] Provider outage degrades to non-AI behavior with a UI notice, never an error page
- [x] LLM responses validated by Zod before use; invalid output discarded safely

## Implementation
`anthropic.ts` (Messages API) + `ollama.ts` (`/api/chat`), selected purely by env via the factory. Shared `http.ts` adds AbortController timeouts + backoff retries and normalises every failure to `AiUnavailableError`. Structured outputs Zod-validated; invalid discarded. Verified live: configured-but-down provider degrades to a clean 503 / SSE error event, never an error page.
