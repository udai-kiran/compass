## Enhancement — per-user portable archive with files + self-service restore

The original instance backup covered DB rows only; uploaded files in object
storage (attachments, insurance/policy documents, health cards, card statements)
were outside it, and there was no in-app restore.

- **Per-user archive** (`.cmpb`, v2 `CMPB2` envelope): one user's rows *and every
  referenced storage object*, streamed through gzip→AES-256-GCM at constant
  memory. Encrypted with a **user-chosen passphrase**, so it's portable to any
  instance. `lib/backup-archive.ts` (length-prefixed header + file frames),
  `lib/crypto-backup.ts` (`encryptBackupStream` / `decryptBackupV2File`),
  `services/backup.ts` (`buildUserBackupStream`, `FILE_COLUMNS`).
- **Restore into a fresh account** (`services/restore-user.ts`): re-homes rows to
  the new `user_id`, re-uploads blobs, rewrites storage keys, all transactional
  with blob-cleanup on failure. Guarded to empty accounts.
- **Orphan report** (`Storage.list()` + `orphanedStorageKeys`): report-only list
  of unreferenced objects.
- Routes under `/api/backup/{archive,restore,orphans}`; UI in Settings → Data.
- Fixed a latent full-restore bug: `transactions.policy_id` now deferred to the
  second pass (insurance_policies restores after transactions).
- Drift guard: a test asserts every `stored_path`/`document_path` column in the
  schema is covered by `FILE_COLUMNS`.
