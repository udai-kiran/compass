Routes: health, auth, profile, notifications, backup. Tables: users, user_profiles, family_members, notification_prefs, notifications, alert_ledger.

Note: `projection_settings` is **not** a system table — task 0.3 placed it physically in the planning module and task 1.5 migrated the rest of planning around it, so it is owned by `modules/planning/`. It was listed here in an earlier draft of the roadmap; that was a duplication with 1.5's table list, now removed.

The riskiest module to move because it holds the cross-cutting guards. `plugins/auth.ts` and `plugins/security.ts` stay app-level (they must apply to every module), but their interaction with per-module plugin encapsulation needs explicit verification — Fastify hook scoping is exactly what changes when routes move into encapsulated plugins.

`/health` is the one non-`/api` public route and must stay public.
