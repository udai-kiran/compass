Photograph a handwritten or printed list and get the same structured, reviewable items as 4.4.

Server-side: image → `Storage` → the vision path from 3.1 → the same tool spec and Zod validation as paste-text. Client-side: extend the existing upload pattern (`FormData` → raw `fetch`, as in `TransactionDrawer.tsx:299-333`) with `capture="environment"` — there is no camera, dropzone or `FileReader` code in the app today.

## Acceptance criteria
- [x] Photo upload → structured items, sharing the 4.4 parse/validate path
- [x] Size and content-type limits enforced with a clear error
- [x] A photo that yields nothing readable degrades to an empty review, not an error page
- [x] Images stored via the `Storage` abstraction (S3 and disk both verified)
- [x] A non-vision / disabled provider degrades with a clear message (no crash)
- [x] typecheck + lint + test green

**Done.** Committed on `feat/shopping-core-capture`. `POST /api/shopping/parse-image` (multipart,
jpeg/png/webp, magic-byte + 5 MB checks) reuses 9.4's `PARSE_LIST_TOOL` + shared `itemsFromTurn` via the
8.1 vision path; adds `AiProvider.supportsVision` (conservative model allowlist) so text-only providers
degrade gracefully; image stored transiently via `Storage` and deleted after the call. Review-only;
records `shopping_parse`. Codex code review clean after iteration 2 (vision-allowlist tightening +
non-vacuous event test). No migration. Camera/picker UI transferred to 12.1 (see Scope note above).
