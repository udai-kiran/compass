Split out of the deduction basket precisely because **a nudge is only correct once the regime is known**. Under the new regime — the default since FY 2023-24 — almost no 80C/80D deduction applies, so telling such a user to "use your remaining ₹38k of 80C headroom" is actively wrong advice, not merely unhelpful.

Deadline-aware prompts, gated on the regime result from 11.8:
- 80C/80D headroom with days remaining to 31 March — **old regime only**
- PPF minimum contribution before dormancy (11.6)
- advance-tax instalment dates (11.10)
- ELSS lock-in and tax-saver FD maturity awareness (11.3, 12.3)

For a new-regime filer the honest output is "chasing 80C is pointless for you" — which is more useful than a tidy progress bar, and is the thing no other app will tell them.

Reuse the notification infrastructure and `alert_ledger` dedup rather than a parallel reminder system.

## Acceptance criteria
- [ ] Nudges suppressed for new-regime users, **with the reason shown** rather than silently hidden
- [ ] Days-to-deadline surfaced; escalation as 31 March approaches
- [ ] Deduped via `alert_ledger`; honours notification preferences
- [ ] Never fires when the user has no actionable headroom
- [ ] Advance-tax reminders ahead of each statutory instalment date
- [ ] typecheck + lint + test green

## Implementation notes (round-3 review pass)

Fixes from independent review:

- **Atomic `fireOnce`** — the `alert_ledger` dedup insert and notification
  creation now share one transaction; a post-insert failure no longer burns a
  dedup key without the user ever seeing the nudge.
- **Sec 208 gate on advance-tax reminders** — instalment nudges now run the
  real `getAdvanceTaxPosition()` and fire only when net payable after TDS is
  ≥ ₹10,000; TDS-covered / sub-threshold users are no longer nagged.
- **PPF/SSY dormancy, ELSS unlock & tax-saver FD maturity implemented**
  (previously listed in the brief but absent): dormancy reuses
  scheme-compliance's own status and escalates on the SAME 90/30/7-day tiers as
  80C/80D (dedup keyed per tier, so it can re-fire as 31 March approaches —
  an earlier draft fired once per FY immediately after 1 April and then never
  again); ELSS/FD use a 30-day lead window on their fixed dates.
- **§87A old-regime cliff fixed upstream** (13.8's engine): old regime has no
  marginal-relief proviso, so a hard cliff at the rebate threshold replaced the
  invented smoothing.

Deliberate limitation, recorded: the nightly fan-out selects recipients from
users with ≥1 ACCEPTED income event in the current FY. A user whose only tax
data is a PPF/SSY account below minimum, an ELSS lot nearing unlock, or a
tax-saver FD nearing maturity — with no accepted income event this FY — is not
evaluated at all. Widening the recipient query to scheme/deposit/holding owners
was judged not worth its cost for v1: anyone contributing to those instruments
in a given year almost always has an income event recorded too, and the
alternative is pinging dormant accounts. Revisit if real usage disagrees.
