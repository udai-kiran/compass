**Codex review finding: without this, goal and tax advice looks precise while resting on an incomplete ledger.** That is the failure mode that quietly destroys trust in a planning tool — not a wrong number, but a confident number built on three of five accounts.

Compass already holds all the evidence and never assembles it: import batches with rejected and duplicate rows, card statement `matchedCount`/`unmatchedCount`, mailbox ingestion failures, unresolved extracted drafts, account statement periods, stale holding valuations, and net-worth snapshot failures.

Add a per-account monthly close/readiness view: expected statement present or missing, last imported-through date, unreconciled card lines, unresolved drafts, stale valuations, unexplained balance difference — and from those, a **confidence level that advisory features must consume**.

Freshness and completeness are cross-cutting, not an income-model detail. Every advisory result in phases 4, 5, 11, 12 and 13 should be able to say "this is based on data that is 6 weeks stale for 2 of your 7 accounts."

## Acceptance criteria
- [ ] Per-account, per-month completeness view assembled from existing evidence
- [ ] Stale valuations, missing statements and unresolved drafts surfaced with age
- [ ] Unexplained balance difference computed where a statement balance is known
- [ ] Confidence signal exposed as a reusable contract for all advisory features
- [ ] Advisory surfaces display input freshness rather than silently assuming currency
- [ ] Does not nag — reports state, and offers the action that would resolve it
- [ ] typecheck + lint + test green
