**Codex P2.** XIRR exists in `services/xirr.ts` and portfolio XIRR is already exposed, holdings track dividends, valuations and buy/sell events — yet Compass never explains *why* returns changed. A single XIRR number tells you the outcome and nothing about the cause.

Attribute return into its parts:
- capital appreciation versus dividends and interest income
- realised versus unrealised
- **contributions versus market movement** — the distinction most people get wrong, since a portfolio growing because you paid into it is not a portfolio performing
- contribution by asset class and by individual holding
- after-tax return, once the tax engine from 2.1.0 exists

Benchmark comparison **only where the user explicitly selects a benchmark**. Auto-assigning one invites a misleading comparison against an index the portfolio was never trying to track.

Reuse `positionCashFlows`, `holdingEvents`, `holdingValuations`, `getPortfolio()` and net-worth snapshots.

## Acceptance criteria
- [ ] Return decomposed into appreciation, income, realised and unrealised components
- [ ] Contribution effect separated from market effect
- [ ] Attribution by asset class and by holding
- [ ] After-tax return where tax data is available; clearly labelled when it is not
- [ ] Benchmark comparison only on explicit user selection
- [ ] Reuses existing XIRR and cash-flow primitives rather than a second implementation
- [ ] typecheck + lint + test green
