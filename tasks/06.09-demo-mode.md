A public, read-only demo so people can experience the app without signing up
(the instance is single-owner, registration is closed). Opt-in per deployment
via `DEMO_ENABLED`.

## Acceptance criteria
- [x] "Explore the demo" entry on the login/welcome screens when enabled
- [x] Every page is populated with coherent sample data
- [x] No demo action can alter data — writes are rejected server-side
- [x] The seeded demo user is excluded from the owner-bootstrap count

## Implementation
- **Read-only guard** (`plugins/auth.ts`): a demo session carries `demo: true`;
  a single onRequest chokepoint rejects every mutating method (except logout)
  with 403 `DemoReadOnly`. The frontend's global error handler already toasts
  the friendly message, so controls stay visible and clicks explain themselves.
- **Seeded demo user** (`services/demo.ts`, `ensureDemoData`): idempotent; on
  first demo login it creates an `is_demo` user (migration 0036) and populates a
  coherent Indian-context dataset — accounts (bank/cash/investment/2 cards/home
  loan/PPF/EPF), 6 months of transactions, budgets, goals, credit-card details +
  rewards, three insurance policies, MF/stock holdings with cost lots +
  valuations, recurring bills/subscriptions + a home-loan EMI, and net-worth
  history. The real backend computes every derived page from this.
- **Entry**: `POST /api/auth/demo` (public, gated by `DEMO_ENABLED`) mints the
  read-only session; `bootstrap` advertises `demoAvailable`, `me` returns
  `isDemo`. `DemoButton` on Login/Welcome; amber "Demo mode" banner + "Exit
  demo" in `AppLayout`.
- **Bootstrap isolation**: `countUsers` excludes demo users, so a fresh install
  still shows the owner-setup screen even after the demo is seeded.
