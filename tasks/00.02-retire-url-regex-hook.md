Replace the stringly-typed side-effect hook in `app.ts:188-196`:

```js
if (/^\/api\/(transactions|transfers|imports|recurring|inbox)/.test(req.url)) {
  await invalidateUserCache(...); await enqueueBudgetEvaluation(...);
}
```

Cache invalidation and budget evaluation become subscribers to `ledger.mutated`; the services that actually mutate the ledger emit it. Renaming a route or adding a mutating endpoint under one of those prefixes must no longer silently change behaviour.

## Acceptance criteria
- [ ] The regex hook is deleted from `app.ts`
- [ ] `invalidateUserCache` and `enqueueBudgetEvaluation` fire from subscribers, not URL matching
- [ ] Every ledger-mutating service path emits `ledger.mutated` (transactions, transfers, imports, recurring, inbox accept)
- [ ] Budget-eval debouncing (`jobId: eval-${userId}-...`, 5s delay) is preserved unchanged
- [ ] A test proves a mutating write invalidates cache without any URL dependency
