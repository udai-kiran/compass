The gap between "hold 60% equity" and actually doing something. Today `services/goal-allocation.ts` only classifies into `equity | debt | other` — deliberately coarse, and `nps` is intentionally `other` because it spans E/C/G tiers.

Add a layer mapping each allocation leg to **candidate instrument categories for the Indian context**, with the attributes that actually decide suitability: lock-in, taxation, liquidity, and typical horizon fit.

- **Equity leg** — index / flexi-cap equity MF, ELSS (80C, 3-year lock-in), equity ETF, direct stocks
- **Debt leg** — PPF, EPF/VPF, short-duration & corporate-bond debt MF, FD/RD, SGB, liquid funds for near-term goals
- **NPS** — spans both, tier-aware

**Hard rule: categories, never named schemes or AMCs.** The app says "a short-duration debt fund suits this leg" and explains why; it never says "buy fund X". This keeps Compass squarely a planning tool rather than something masquerading as a registered investment adviser, and it is also just more honest — the app has no view on any specific product. Every suggestion states its assumptions and is grounded in accounts/holdings the user already has where possible.

## Acceptance criteria
- [ ] Instrument categories modelled with lock-in, tax treatment, liquidity and horizon fit
- [ ] Each allocation leg maps to ranked candidate categories with a stated rationale
- [ ] Suitability respects the goal horizon (no ELSS 3-year lock-in for an 18-month goal)
- [ ] Prefers categories the user already holds or has an account for, before proposing anything new
- [ ] **No named scheme, fund or AMC is ever emitted** — enforced by test
- [ ] Assumptions (returns, inflation) surfaced from `projection_settings`, never hidden
- [ ] Pure, deterministic and unit-tested — no model call
- [ ] typecheck + lint + test green
