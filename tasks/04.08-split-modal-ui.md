> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Files:** `src/routes/transactions/SplitModal.tsx` (new — copy the a11y template from `RecordEpfModal.tsx`), a balances panel on `src/routes/household/HouseholdPage.tsx`, `src/lib/household-queries.ts`.

- **Split modal** launched from a transaction: choose members, choose a rule (equal / shares / exact), with a **live running total that always reconciles to the transaction amount**. An exact split that does not add up cannot be submitted, and the shortfall is shown as a number rather than a generic validation message.
- **Equal splits with a remainder** (₹100 across 3) must show where the leftover paisa went. Silently dropping it is how users lose trust in a split feature.
- **Balances panel** — "Priya owes you ₹1,240", netted per person, not per transaction.
- **Settle up** — records the settling transfer and zeroes that pair. Make clear it records a payment and does **not** move money.

All amounts via `formatINR`. No currency arithmetic in the component — derive in a tested sibling module per `UI.md`.

## Acceptance criteria
- [ ] All three split rules with a live total that reconciles to the transaction amount
- [ ] Remainder allocation visible, not silent
- [ ] Unbalanced exact split blocked, with the shortfall shown numerically
- [ ] Balances netted per person; settle-up records a transfer and zeroes the pair
- [ ] Copy makes clear no money is moved
- [ ] Split math lives in a tested sibling module, not JSX
- [ ] Modal is `role="dialog"`, Escape-closable, focus-trapped
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
