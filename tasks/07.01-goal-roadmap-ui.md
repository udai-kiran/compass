> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Extends `/goals` — do not create a parallel `/planning` route.** Goal progress, funding and linked SIPs already live there; splitting planning away would fragment the story.

**Files:** `src/routes/goals/GoalsPage.tsx`, new `src/routes/goals/RoadmapPanel.tsx`, `src/routes/goals/roadmap-view.ts` (+ `.test.ts`), `src/lib/goal-queries.ts`.

Render the forward glide path from 5.1: the allocation now, the **dated switch points** where the equity/debt mix changes, and the required contribution at each step. Use `LineChart` / `Columns` / `Meter` / `StatTile` from `src/lib/viz.tsx` — no charting library.

The switch points are the actionable part. A smooth gradient looks pretty and tells the user nothing; "in March 2029 this goal moves from 60/40 to 40/60" is something they can plan around.

**Show the assumptions** — return and inflation come from `projection_settings` and must be visible, not buried. A projection whose basis is hidden invites false confidence.

## Acceptance criteria
- [ ] Forward glide path rendered with dated switch points clearly marked
- [ ] Required contribution shown per step
- [ ] Return/inflation assumptions visible on the panel
- [ ] Undated goals and emergency funds render sensibly (no path to glide) rather than erroring
- [ ] Built only from `viz.tsx` primitives
- [ ] Derivation logic in `roadmap-view.ts` with tests; none in JSX
- [ ] Chart scrolls within its own container on narrow screens
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
