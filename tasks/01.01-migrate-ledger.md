First real migration — the largest domain, and the template for the remaining seven.

Routes: accounts, categories, transactions, transfers, transaction-links, attachments, recurring, rules, resources, search, user-tasks. Tables: accounts, categories, resources, transactions, transaction_splits, transfer_links, transaction_links, attachments, merchant_rules, recurring_templates, user_tasks. Heaviest services: `accounts.ts` (507), `transactions.ts` (441).

Schema slice → services moved under `modules/ledger/` → a single (unprefixed) Fastify plugin replacing the 11 flat registrations. Behaviour and URLs stayed byte-identical; this was a move, not a rewrite. Table definitions stayed physically in `db/schema.ts` for now (a thin re-export surface in `modules/ledger/schema.ts`, not physical relocation) — see `tasks/007-migrate-ledger/TASK.md` for why, and `tasks/01.09-cross-module-ports.md` (amended by this task) for where physical decomposition eventually happens. The route-identity gate from 0.3 was split into two snapshots during this task (a canonical method+path surface, plus the pre-existing raw `printRoutes()` tree) since collapsing the flat registrations into one plugin legitimately restructures the raw tree without changing the API surface — both now apply to every remaining Phase-1 migration.
