Rate limiting (Redis-backed), CSRF protection, security headers, dependency audit in CI, a11y pass, consistent empty/loading/error states, 404/500 pages.

Implemented in `apps/api/src/plugins/security.ts` (onSend headers + onRequest CSRF/rate-limit),
wired in `app.ts` with `trustProxy: true`. Frontend: `components/States.tsx` (accessible
loading/error/empty), `routes/ErrorPage.tsx` (500 boundary + 404 catch-all), skip-link & nav
landmarks in `AppLayout.tsx`. CI gains `npm test` + an `npm audit --audit-level=high` job.

## Acceptance criteria
- [x] Rate limits on auth and write endpoints — Redis fixed-window buckets (auth 15/5m, write 120/1m, read 600/1m) keyed by client IP; verified 401→429 with `Retry-After`.
- [x] Security headers verified (CSP, HSTS behind proxy) — CSP `default-src 'none'`, X-Frame-Options DENY, nosniff, Referrer-Policy, COOP; HSTS emitted only over TLS (`req.protocol==="https"` via trustProxy). Verified via curl.
- [x] Keyboard-only walkthrough of core flows succeeds — skip-to-content link, `aria-label` nav landmark, NavLink `aria-current`, accessible `role=status`/`role=alert` state components; all controls are native button/input/anchor.

## Also delivered
- CSRF: browser `Origin` verified against request host (+ `TRUSTED_ORIGINS`) on mutating methods → 403 on cross-origin. Non-browser (no Origin) clients unaffected.
- Consistent empty/loading/error primitives (`States.tsx`) and 404/500 pages wired via router `errorElement` + `path:"*"`.
- Dependency audit in CI (`npm audit --audit-level=high`).
