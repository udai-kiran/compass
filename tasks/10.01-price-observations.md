`price_sources` (platform registry) and `price_observations` (timestamped `(catalog_item, source, price_paise, unit_price_paise, observed_via)`), the substrate every later pricing feature reads.

**Platform registry** — seed with the Indian quick-commerce and grocery set that comparators like [Comparify](https://comparify.pro/) cover: **Blinkit, Swiggy Instamart, Zepto, BigBasket, JioMart, DMart, Flipkart, Amazon (incl. Amazon Now), DealShare, MilkBasket**, plus a manual "local kirana" source. Platforms differ in delivery fee, minimum cart and serviceability, so the registry carries those as first-class fields rather than assuming they are comparable.

**Data acquisition is deliberately limited to what is legal and durable:** user-submitted prices, receipt OCR, and official affiliate APIs. Live scraping of quick-commerce platforms stays out of core — if ever built it is a disabled-by-default pluggable adapter, isolated exactly like the `email` compose profile.

Every displayed price must carry its source and observation time. Crowdsourced data is not live truth and must never be presented as though it were.

## Acceptance criteria
- [ ] Manual price entry works and is attributed to a source
- [ ] Every price surfaced with source + "last observed" timestamp
- [ ] Stale observations visibly marked
- [ ] No scraping code in core; adapter interface documented but unimplemented
- [ ] Tables added to `ALL_TABLES`/`USER_TABLES`
- [ ] typecheck + lint + test green
