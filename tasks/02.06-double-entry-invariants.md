Closes the phase by making the guarantees enforceable rather than aspirational. A double-entry ledger whose invariants are only checked at write time drifts the first time something writes around the service layer.

Assert continuously:
- **every transaction sums to zero** — no exceptions, no tolerance
- **the whole ledger sums to zero** across all accounts including system accounts
- **account balance equals `sum(postings)`** with no second source
- **no orphan postings** — every posting belongs to a transaction that still exists
- **soft-deleted transactions remove all their legs together**, never a subset

Expose an operator-facing integrity check (reusing the pattern of the existing backup orphan report) that can be run on demand and reports any imbalance with the offending transaction ids, rather than a bare boolean.

Per `TDD.md`, these are **property tests over generated data**, not example tests. Hand-picked cases miss exactly the rounding and partial-failure paths where a paisa goes missing, and a ledger that is off by one paisa is a ledger nobody trusts.

## Acceptance criteria
- [ ] Property tests: generated transactions always balance; generated ledgers always sum to zero
- [ ] Balance-equals-postings asserted across generated account histories
- [ ] Orphan-posting and partial-delete cases covered
- [ ] On-demand integrity check reporting offending transaction ids, not a boolean
- [ ] A deliberately corrupted fixture is detected by the check (the test that proves the guard works)
- [ ] Concurrent writes cannot commit a half-balanced transaction
- [ ] typecheck + lint + test green
