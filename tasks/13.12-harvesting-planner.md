Add:
- unrealised gain/loss per **open lot**
- lots approaching long-term status, with the date they cross
- equity LTCG exemption headroom for the current FY
- loss-offset opportunities against realised gains, ordered per 11.11
- harvest-and-rebuy caveats, including the fact that rebuying resets the holding period
- estimated tax effect with transaction cost and exit load assumptions stated

Share a **tax-position service** with rebalancing rather than becoming a second, divergent calculator — that duplication is exactly how two features start disagreeing about the same portfolio.

## Implementation notes (post-review pass)

Independent Codex review found real defects; all fixed in this pass:

- **NAV units** — `holdingValuations.nav` is rupees/unit; the planner now
  converts ×100 to paise (regression-pinned by an assembler test).
- **§112A gating** — gain harvesting is offered ONLY on long-term equity lots;
  short-term and non-equity gains are never suggested.
- **Loss value capped by real pools** — a harvested loss is allocated against
  this year's actually realised STCG/LTCG (§70/§74 order, best rate first);
  the STCL spill onto LTCG is valued at 12.5%, not 20%. A loss with nothing to
  offset is not suggested. Costs price off redemption PROCEEDS, not P&L.
- **Headroom flooring** — realised equity LTCG is floored at zero before the
  exemption is consumed (a net LTCL no longer inflates headroom or emits a
  negative figure).
- **Crossover day** — `ltcgCrossoverDate` returns the day AFTER the clamped
  anniversary: on the anniversary itself the lot is still short-term.
- **Locked ELSS lots stay in positions** — they still own part of a holding's
  value, so excluding them misallocated manual valuations; they are excluded
  from suggestions only.

Deliberate deviation, recorded: the brief says harvesting should "share a
tax-position service with rebalancing". Both features already share THE single
FIFO calculator (`tax-lots.ts` `realizeGains`) and the same §112A exemption
constant — there is no second calculator. What harvesting adds on top is a
purpose-specific valuation layer (unrealised lots, guessed friction) that
rebalancing neither wants nor uses; extracting a shared service would couple
two different questions to one response shape. Not done, intentionally.

## Implementation notes (round-2 review pass)

The review found the realised-side pools were computed per-class independently,
which mis-models §70/§74 set-off and the §112A exemption. Rewritten:

- **Signed-sum netting** — realised STCG/LTCG are accumulated as signed sums
  and intra-term netted FIRST: `stcgPool = max(0, Σst)`, equity-LTCL absorbs
  non-equity LTCG before equity LTCG (deterministic order), residual STCL spills
  STCG → taxable LTCG. A net STCL now correctly consumes realised LTCG.
- **Losses valued against TAXABLE gains only** — the ₹1.25L exemption is
  consumed by POST-set-off equity LTCG; only the slice beyond it is taxed at
  12.5%, so offsetting losses inside the exemption save nothing.
  `taxableLtcgPool = nonEquityLtcg + max(0, equityLtcg − exemption)`.
  Pinned by tests: spill valued at 12.5% (`grossTaxEffectPaise === 62_500`),
  and no loss suggestion at all when realised gains sit wholly inside the
  exemption.
- **Two-phase candidate ranking** — ALL candidates are ranked by estimated net
  benefit BEFORE scarce capacity (headroom, loss pools) is consumed; cheap cost
  pre-filters stop worthless losses from draining pools ahead of profitable ones.
- **Exempt-class losses excluded** — an exempt disposal creates no taxable
  loss; non-equity lots carry a slab-rate caveat since §50AA/STCG on them is
  slab-taxed, not flat 20%.

Regression suite rewritten around these semantics (24 tests), including the
NAV-is-rupees-per-unit ×100 pin and ELSS locked-lot handling.

## Implementation notes (round-2/3 review passes)

Fixes from independent review:

- **Brought-forward losses now feed the planner (13.11's "never double-counts"
  criterion)** — `getTaxHarvestPlan()` calls `getCapitalPosition()` (the same
  source advance-tax uses). Brought-forward absorption reduces the STCG and
  taxable-LTCG pools before suggestions are ranked, so a harvested loss cannot
  claim gain capacity a prior-year loss already consumed, and reported
  headroom matches the rest of the tax surface.
- **§112A headroom is EQUITY-ONLY** — `netLtcgPaise` from
  `getCapitalPosition()` combines equity+non-equity LTCG; using it directly let
  ₹2L of non-equity gains wrongly zero out equity exemption headroom. The
  combined brought-forward absorption is re-allocated across the local pools
  non-equity-first (mirroring this file's own §70 convention), and headroom is
  derived from post-absorption equity LTCG only. Regression test: non-equity
  LTCG alone no longer consumes the exemption.
- **Exempt slices excluded** — realised `"exempt"` slices (tax-free bond
  redemptions, SGB at maturity) no longer land in the short-term pool via a
  catch-all else; bucketing is exhaustive over `GainTerm`.
- **Pool capacity is reserved only for ACCEPTED candidates** — the loss loop
  decremented `stcgPool`/`taxableLtcgPool` before the final net-benefit check,
  so one cost-dominated candidate could drain both pools and silently exclude
  a later profitable one. Decrement now happens after acceptance; regression
  test proves the second candidate survives.
- Zero-cost open lots (bonus units) are no longer dropped by `realizeGains()`'s
  `costPaise > 0` filter.
