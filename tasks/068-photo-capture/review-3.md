**Findings**

BLOCKING: `modelSupportsVision()` is not conservative enough for AC5. It returns true for any model string containing `claude`, `gemini`, `llava`, `-vl`, or `vision` via broad substring checks in [types.ts](/work/personal/compass/packages/ai/src/types.ts:265). Because OpenAI-compatible providers set `supportsVision` directly from that helper in [openai-compat.ts](/work/personal/compass/packages/ai/src/openai-compat.ts:75), a text-only custom/OpenRouter model alias such as `my-vision-benchmark-text-model`, `not-vision`, or an older/text-only `claude`-named route would pass the gate in [parse-image.ts](/work/personal/compass/apps/api/src/modules/shopping/services/parse-image.ts:77) and then send an image to `ai.chat()` in [parse-image.ts](/work/personal/compass/apps/api/src/modules/shopping/services/parse-image.ts:98). That regresses the approved “unknown/text-only OpenAI-compatible models degrade gracefully without chat/store” goal for any false-positive model string. The helper does correctly return false for `deepseek-chat`, `deepseek/deepseek-chat`, empty, and unknown strings, and it returns true for the tested known families.

non-blocking: The route event-recording test for image capture is vacuous. The real route builds a `shopping_parse` observer in [capture-image.ts](/work/personal/compass/apps/api/src/modules/shopping/routes/capture-image.ts:104) and passes it to `parseListImage` in [capture-image.ts](/work/personal/compass/apps/api/src/modules/shopping/routes/capture-image.ts:117), but the hermetic mock ignores all arguments and never calls `observe` in [capture-image.hermetic.test.ts](/work/personal/compass/apps/api/src/modules/shopping/routes/capture-image.hermetic.test.ts:29). So AC6’s “shopping_parse recorded” is implemented, but not proven non-vacuously for the image route. The text route has the better pattern: its mock calls `observe` in [capture.hermetic.test.ts](/work/personal/compass/apps/api/src/modules/shopping/routes/capture.hermetic.test.ts:60).

non-blocking: Oversize uploads do surface as 413, but the curated “5 MB limit” branch is likely bypassed by `@fastify/multipart` default behavior because `file.toBuffer()` is awaited before checking `file.file.truncated` in [capture-image.ts](/work/personal/compass/apps/api/src/modules/shopping/routes/capture-image.ts:76). The global handler will still return the plugin’s 413 via [app.ts](/work/personal/compass/apps/api/src/app.ts:239), and the test asserts status 413, but the approved plan’s clearer `"...5 MB..."` message is not guaranteed.
