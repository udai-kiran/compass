> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Files:** new `src/routes/goals/InstrumentPanel.tsx`, `src/routes/goals/instrument-view.ts` (+ `.test.ts`).

Show the ranked instrument **categories** for each allocation leg with the attributes that actually decide suitability — lock-in, tax treatment, liquidity, horizon fit — and the stated rationale from 5.3.

**Never render a named scheme, fund or AMC.** This is enforced by test on the backend and must hold in the UI: no free-text field, tooltip or example may name a product. The correct phrasing is *"a short-duration debt fund suits this leg because…"*, never *"buy X Fund"*.

Prefer categories the user already holds — surfacing "you already have this" is more useful than a generic recommendation, and it is the part that makes the guidance feel like it knows them.

## Acceptance criteria
- [ ] Ranked categories per leg with lock-in, tax, liquidity and horizon shown
- [ ] Rationale displayed alongside each suggestion
- [ ] Categories the user already holds visibly distinguished from new suggestions
- [ ] **No named product anywhere in the rendered output** — covered by a test
- [ ] Suitability conflicts (e.g. a 3-year lock-in against an 18-month goal) shown as a warning, not hidden
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
