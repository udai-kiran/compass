> **Read [`UI.md`](./UI.md) first** — stack, the components that already exist, the three-edit nav rule, and the conventions this repo enforces. Do not add a UI or charting library.

**Files:** new `src/routes/goals/AllocationPanel.tsx` and `src/routes/goals/LeverPanel.tsx`, `src/routes/goals/allocation-view.ts` (+ `.test.ts`).

- **Allocation** — how the investable surplus splits across competing goals, with **goals that slip named explicitly and by how long**. Do not present a tidy pie chart that conceals an unfunded goal.
- **Levers** — the four ways to close a shortfall (extend timeline, cut target, cut expenses, increase income) as comparable options with real numbers, including the income lever expressed in both rupees and percent.
- **Confidence** — the surplus figure has a conservative and an optimistic band (6.1). Show both. A single number implies a precision the model does not have.

**Tone matters more here than anywhere else in the app.** A user seeing "you cannot afford your goals" needs the levers beside it, presented as choices. No red banners, no scolding, no implied judgement about their spending.

## Acceptance criteria
- [ ] Per-goal allocation with slipping goals named and quantified in months
- [ ] All four levers with real figures; income lever in ₹ and %
- [ ] Conservative and optimistic surplus both shown
- [ ] Combinations of levers explorable, not a single prescribed answer
- [ ] Neutral, non-scolding presentation of a shortfall
- [ ] Zero-surplus and single-goal cases render correctly
- [ ] typecheck · lint · test · `npm run build -w apps/web` all pass
